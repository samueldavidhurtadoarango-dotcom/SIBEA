# Vistas de BenefitRack — Plan de implementación

> **Para agentes:** SUB-SKILL OBLIGATORIA: superpowers:subagent-driven-development (lo exige el manual global §1: el orquestador delega, verifica y pide revisión). Los pasos usan casillas (`- [ ]`).

**Objetivo:** construir, como maquetas HTML estáticas con capturas para computador y celular, las 9 vistas de `specs/002-vistas.md`.

**Arquitectura:** cada estado de cada vista se escribe como **fuente** en `vistas/_fuente/<NN>-<vista>/<estado>.html`, que usa un CSS común y piezas compartidas (barra del aprendiz, menú del administrador). Un script `construir.js` genera la **salida autocontenida** en `vistas/<NN>-<vista>/html/<estado>.html` (CSS incrustado, piezas resueltas) y saca las capturas PNG con Edge vía `playwright-core`. Un script `verificar.js` es la suite de pruebas: lee `vistas/estados.json` (la lista de estados que exige la spec) y los archivos de prueba por vista, y falla si falta algo o si no se cumple un criterio de aceptación.

**Tecnología:** HTML + CSS sin frameworks; Node 24; `playwright-core@1.48.2` usando el Edge instalado (`channel: 'msedge'`, sin descargar navegadores); `axe-core@4.10.2` para el contraste. Las dependencias se instalan **fuera del repositorio** y se apuntan con `NODE_PATH`, como en `herramientas/LEEME.md`.

**Spec:** `specs/002-vistas.md` (aprobada por Samuel el 2026-11-08). Quien ejecute el plan lee los dos documentos.

## Restricciones globales

- Letra: `'Work Sans', Inter, system-ui, sans-serif`. Colores **solo** de la paleta de la spec §2: `#00304D`, `#007832`, `#00632A`, `#6BD11F`, `#0B6CB8`, `#556776`, `#6B7C88`, `#7D8E9A`, `#F5F7F9`, `#F0F4F6`, `#EEF2F4`, `#E3E8EC`, `#FFFFFF`. Además, los de aviso del boceto aprobado: naranja `#FFF3E0` / `#A35200` / `#F5C98B` / `#7A3E00` y verde claro `#E6F4EC`. Si se necesita otro color, se agrega aquí antes de usarlo.
- Cada HTML de salida es autocontenido: `<meta charset="utf-8">`, CSS incrustado, sin scripts externos. Lo único externo permitido es Google Fonts, con su respaldo.
- Capturas: `computador/<estado>.png` a **1440 px** de ancho y `celular/<estado>.png` a **390 px**, de página completa.
- Sin desplazamiento horizontal a 390 px. Contraste de texto ≥ 4.5:1 (axe `color-contrast` sin fallos).
- Textos en español con tildes y ñ. Datos de ejemplo: nombres colombianos inventados, `$ 180.000`, fechas «15 nov 2026». Nunca nombres del equipo (Samuel, Santiago, Mariana, Dylan).
- Ninguna vista del aprendiz tiene botones ni enlaces para postularse (CA-3).
- Menú del administrador, igual en todas sus vistas: **Dashboard · Convocatorias · Postulaciones · Pagos · Usuarios** (sin Auditoría).
- Skill `impeccable` en modo «Operate» para todo agente que diseñe (manual §5.1).
- **Puerta de Samuel:** cada vista se le muestra en el navegador de bocetos y no se hace commit «verde» de la vista sin su «sí». Sus cambios se aplican antes de pasar a la siguiente.
- Rama `feat/002-vistas`. Commit de la fase roja (`test:`) y de la fase verde (`feat:`) en cada tarea.

## Atención en la revisión

1. **Nombres y montos largos a 390 px** (por ejemplo «María Fernanda Castañeda Villalobos», `$ 12.500.000`, 6 o más filas de pagos): deben ajustarse sin desbordar. Lo cubre la comprobación global de desbordamiento, y cada vista incluye al menos un estado con nombre largo en sus datos (tareas 2–10).
2. **Codificación de tildes y ñ:** si falta `charset`, aparece «Ã±». Comprobación global de `<meta charset="utf-8">` y prueba de texto «Información» renderizado (tarea 1).
3. **Foco visible y teclado en diálogos** (confirmar aprobación, pago masivo, pedir documento): cada botón e input tiene `:focus-visible` con contorno. Comprobación global en la tarea 1: el CSS común define `:focus-visible`; axe sin fallos de `button-name` ni `label`.
4. **Botones deshabilitados que no explican por qué** (Aprobar sin cupos, Datos confirmados con documento pendiente): debe haber un texto visible cerca. Pruebas en las tareas 4 y 2.
5. **Estados vacíos y sin conexión a datos** (sin postulación, sin convocatorias, sin aprobados, sin avisos): cada uno tiene su HTML con un mensaje y una acción. Lo cubre `estados.json` (CA-8).
